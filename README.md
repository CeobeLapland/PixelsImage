# PixelsImage · 像素工坊

把高清图变成 Minecraft 风格的**低分辨率像素图**，并且能像画像素画一样**逐块手工微调**。
为美术素材创作做的本地小工具：图片全程不离开你的电脑，无后端、无上传。

> 状态：**M5 已完成**（批量处理：多图队列 / 逐项覆盖 / 命名模板 / 一次打出 zip）。
> 剩下的导出扩展（图集、GIF、蓝图）与存档在 M6–M7，见 [docs/ROADMAP.md](docs/ROADMAP.md)。

---

## 这个工具解决什么问题

用 AI 或照片生成的图，想转成 Minecraft 那种「一格一色」的方块美学，通常只有两条路：

1. 用 Photoshop 缩小 + 手动数格子改色 —— 累，且改一个主色调要全图重来；
2. 用在线转换器 —— 出来就是一坨死图，颜色数、抖动方式、透明度都不受控，更没法手改。

PixelsImage 想做的是中间那条路：**转换参数随时可调、调色板随时可换、手工改的部分永远不会丢**。
换尺寸、换调色板、换抖动算法，你手画的那些像素依然在原位。

---

## 核心工作流

```
拖入高清图
  → 设定目标像素尺寸（如 32×32 格）与采样方式
  → 选调色板（Minecraft 16 色 / PICO-8 / GameBoy / 自定义 .hex）
  → 选量化距离与抖动算法，实时预览
  → 在画布上手工微调（铅笔 / 油漆桶 / 对称镜像 / 一键全局换色）
  → 导出：PNG（1x 或 16x 放大）、精灵图集、调色板、GIF、Minecraft 建造蓝图
```

## 特性总览

### 转换引擎
- **降采样**：最近邻 / 面积平均 / 主色投票 / 中值，可选择是否保留硬边缘
- **目标尺寸**：按格数指定（16 / 32 / 64 / 128 / 自定义），自动保持宽高比，支持非等比拉伸
- **颜色量化**：
  - 映射到固定调色板（预设或自定义）
  - k-means 限制色彩数（自动从原图提取 N 个主色）
  - 距离度量可选：欧氏 RGB / 加权 RGB（人眼感知） / CIELAB ΔE
- **抖动算法**：无 / 有序 Bayer 2·4·8 / Floyd–Steinberg / Atkinson / Sierra，强度可调
- **预处理**：亮度、对比度、饱和度、锐化、alpha 阈值（一键抠背景）
- **实时预览**：所有参数改动即时重算，可侧滑分割对比原图

### 调色板引擎
- 内置 9 块调色板：Minecraft 染料 16 / MC 混凝土 16 / PICO-8 / GameBoy 4 / NES 子集 24 /
  C64 / DawnBringer 16 / 灰阶 8 级 / 黑白 2 色
- 从图片自动提取主色（中位切分 / k-means），可排除透明像素、限定明度区间
- 导入 / 导出 `.hex`、`.gpl`（GIMP Palette）、`.pal`（JASC-PAL）、色条 PNG
- **一键全局换色**：`Shift+点色块` 把全图某色替换成前景色（含手改区域，可 Ctrl+Z 撤销）—— 改素材主色调不用重画
- 逐个色槽改色（原生取色器）、按明度/色相排序、合并近似色
- 自定义调色板持久化，关掉浏览器再打开依然在
- k-means 限色模式：让图片自己决定用哪 N 种颜色

### 像素编辑器
- 工具：铅笔、橡皮、油漆桶填充、吸管、直线、矩形、椭圆、选区移动
- 撤销 / 重做（100 步命令栈）
- 缩放 1x–64x、网格线开关、像素坐标与色号实时显示
- **对称镜像**：水平 / 垂直 / 四向 —— 做角色素材的神器
- **双层模型**：转换结果是底层，手工改动叠加在编辑层；调转换参数不会毁掉你的手改
- 原图半透明叠加对照（onion skin）

### 智能辅助
- **自动描边**：给非透明区域外缘自动加 1px 轮廓（可选 4/8 邻域与外缘/内缘/两侧）
- **自动明暗**：按亮度自动分层为高光 / 中间调 / 阴影，**不改变色相** —— 只压明暗层次，红苹果不会被压成灰色
- **去背**：α 阈值判背景 + 边缘色晕清理（消除半透明像素残留的背景色，绿幕边、白底灰边）
- **平铺预览与接缝检查**：3×3 重复预览直接看无缝效果，对不上的边界格在画布上标红
- 原图半透明叠加对照（onion skin），描线时对位置
- 以上操作全部写进手改层，**每一个都能 Ctrl+Z 撤销**

### 导出
- PNG：1x 原始像素，或 2x–64x 最近邻放大（不发虚）
- 精灵图集：多图/多帧按行打包 + 可选裁剪透明边
- 调色板文件：`.hex` / `.gpl` / 色条 PNG
- JSON 网格数据：`{w, h, palette, indices}` —— 给程序消费
- GIF：动画逐帧像素化后重新编码
- **Minecraft 建造蓝图**：网格 + 坐标轴 + 色号图例，导出可打印的大图或 `x,y,z,block` CSV，照着在游戏里搭
- 项目存档 `.pixproj`：参数 + 调色板 + 手工编辑全部可存可读

### 批量处理
- **多图队列**：一次拖入一批图（也可点选多选），逐项缩略图 + 状态（待处理 / 转换中 / 完成 / 失败）
- **共用一套批量参数**，个别项可单独改目标格数
- **命名模板**：`{name}` / `{w}` / `{h}` / `{scale}` / `{index}`，同名自动去重（不区分大小写，避免 Windows/macOS 上互相覆盖）
- **一次打出 zip**：每张图的 PNG + 用到的调色板 `.hex` + `report.txt`（逐张尺寸/用色/耗时）
- 队列里任意一项可**送进主编辑器单独微调**（源图与参数一起带过去）
- **批处理预设**：参数 + 命名模板 + 放大倍数一起存取
- 批量转换跑在**独立的 Worker** 上，后台出素材的同时编辑器照常可用

## 快速开始

```bash
npm install
npm run dev      # 打开 http://localhost:5173
npm test         # 运行 core/ 层的单元测试
npm run build    # 产出 dist/，用任意静态服务器托管即可（如 npx serve dist）
```

> 目前 `dist/` 需要用静态服务器打开：产物是 ES module，浏览器不允许通过 `file://`
> 直接加载。真正做到「双击即用」需要把资源内联进单文件，安排在 M7。

### 已可用的操作

| 操作 | 方式 |
| --- | --- |
| 导入图片 | 拖到画布上 / `Ctrl+V` 粘贴 / 点「选择文件…」 |
| 缩放画布 | 滚轮（以光标为锚点）/ `+` `-` 键 / 右下角控件 |
| 平移画布 | 拖拽 / 中键拖拽 / 按住 `空格` 拖拽 |
| 适配窗口 | `0` 键 |
| 原尺寸 | `1` 键 |
| 折叠右侧面板 | `Tab` 键 |
| 左右对照扫动 | 拖拽画布上的琥珀色分割线 |
| 切换工具 | `B` 铅笔 · `E` 橡皮 · `G` 油漆桶 · `I` 吸管 · `L` 直线 · `R` 矩形 · `O` 椭圆 · `M` 选区 |
| 笔刷尺寸 | `[` `]`（1–4 格） |
| 临时取色 | 按住 `Alt` 点击（不切换当前工具） |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Shift+Z`（栈深 100） |
| 前景 / 背景互换 | `X` 键 |
| 取消选区 / 清空选区 | `Esc` / `Delete` |
| 导出 PNG | 右侧「导出」分组，可选 1×–64× 整数倍放大，**含手工修改** |
| 取色 / 换色 | 色块**左键**设前景色、**右键**设背景色、**Shift+左键**把全图该色换成前景色 |

**绘图**只在画布显示像素图时生效（「仅结果」视图整张可画，「侧滑分割」视图在右半侧可画）。
手工修改存在独立的编辑层：调整转换参数、换抖动算法都不会覆盖它，只有网格尺寸变化时按比例重采样。

**调色板**（右侧「调色板」分组）：选板、改单个色槽的颜色、排序、合并近似色。
「提取主色」分组可以从当前图聚出 N 个主色并存成自定义板；
「调色板文件」分组负责 `.hex` / `.gpl` / `.pal` 的导入与 `.hex` / `.gpl` / 色条 PNG 的导出。

**批量处理**（右侧「批量处理」分组，默认折叠）：把一批图拖进队列 → 设好这套批量参数
（或点「从当前参数同步」把「转换」面板那套抄过来）→ 开始转换 → 导出 zip。
命名模板里的 `{name}` 是源文件名，`{index}` 是队列序号；同名会自动加 `_2`、`_3`。
队列里每一项都能展开，勾「独立目标格数」单独改尺寸，或点「在编辑器中打开」跳去手改。
手改之后记得点该项上的**「写回队列」**—— 手改住在编辑层里，不写回的话 zip 拿到的还是未经手改的结果。
批量参数是**独立的一份**，所以批量在后台跑的时候，编辑器里的预览照常调。

**颜色来源**（右侧「转换」分组）可在「固定调色板」与「k-means 限色」之间切换 ——
后者让图片自己聚出 N 种代表色，适合「先看看这张图本来长什么样」。

**转换参数**（右侧「转换」分组）：目标格数、采样方式（面积平均 / 最近邻 / 主色投票 / 中位数）、
颜色距离（加权 RGB / CIELAB / 欧氏 RGB）、抖动算法（Atkinson / Floyd / Sierra /
Bayer 2·4·8 / 不抖动）、抖动强度、亮度 / 对比度 / 饱和度 / 锐化 / 透明阈值、
pixelPerfect、裁掉透明边。

转换在 Web Worker 中执行，参数改动即时重算；拖动滑块时会自动降级到加权 RGB 距离
保证跟手，松手后再跑一次完整精度。

## 技术栈

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 构建 | Vite + TypeScript（strict） | 起手快、零配置、可打包成离线静态文件 |
| UI | React 19 | 面板/控件多，组件化收益明显 |
| 状态 | Zustand | 轻量、可在 React 之外读写（画布与工具函数需要） |
| 绘图 | Canvas 2D + OffscreenCanvas | 逐像素操作 API 直接，缩放用 `imageSmoothingEnabled=false` |
| 重计算 | Web Worker | 转换流水线不阻塞 UI，帧数据通过 transferable 零拷贝传递 |
| 可选依赖 | `gifenc`（GIF 编码，M6 按需引入） | 只在 GIF 导出时用到 |

**无后端、无网络请求**：所有图像处理在浏览器本地完成。

## 设计原则

1. **参数可逆，手改不丢** —— 转换与手工编辑分层存储；调参数不会清掉你画的东西。
2. **纯本地** —— 不联网、不上传、不依赖账号。
3. **逻辑与 UI 分离** —— `core/` 是纯函数，可单独测试，将来换 UI 或做 CLI 都不用重写。
4. **不追求全自动** —— 自动算法负责出草稿，最终效果由你的手决定。
