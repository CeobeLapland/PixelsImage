# PixelsImage · 像素工坊

把高清图变成 Minecraft 风格的**低分辨率像素图**，并且能像画像素画一样**逐块手工微调**。
为美术素材创作做的本地小工具：图片全程不离开你的电脑，无后端、无上传。

> 状态：**M0–M7 全部完成**（M7：存档 / 预设 / 快捷键面板 / 离线单文件 / 命令行批量转换）。
> 可选的扩展项（底色可选、明度阶梯、并排对比、`.ase` 导出、CLI）也已补齐，见 [docs/ROADMAP.md](docs/ROADMAP.md)。

---

## 这个工具解决什么问题

用 AI 或照片生成的图，想转成 Minecraft 那种「一格一色」的方块美学，通常只有两条路：

1. 用 Photoshop 缩小 + 手动数格子改色 —— 累，且改一个主色调要全图重来；
2. 用在线转换器 —— 出来就是一坨死图，颜色数、抖动方式、透明度都不受控，更没法手改。

PixelsImage 想做的是中间那条路：**转换参数随时可调、调色板随时可换、手工改的部分永远不会丢**。
换尺寸、换调色板、换抖动算法，你手画的那些像素依然在原位。

---

## 核心工作流

```
拖入高清图
  → 设定目标像素尺寸（如 32×32 格）与采样方式
  → 选调色板（Minecraft 16 色 / PICO-8 / GameBoy / 自定义 .hex）
  → 选量化距离与抖动算法，实时预览
  → 在画布上手工微调（铅笔 / 油漆桶 / 对称镜像 / 一键全局换色）
  → 导出：PNG（1x 或 16x 放大）、精灵图集、调色板、GIF、Minecraft 建造蓝图
```

## 特性总览

### 转换引擎
- **降采样**：最近邻 / 面积平均 / 主色投票 / 中值，可选择是否保留硬边缘
- **目标尺寸**：按格数指定（16 / 32 / 64 / 128 / 自定义），自动保持宽高比，支持非等比拉伸
- **颜色量化**：
  - 映射到固定调色板（预设或自定义）
  - k-means 限制色彩数（自动从原图提取 N 个主色）
  - 距离度量可选：欧氏 RGB / 加权 RGB（人眼感知） / CIELAB ΔE
- **抖动算法**：无 / 有序 Bayer 2·4·8 / Floyd–Steinberg / Atkinson / Sierra，强度可调
- **预处理**：亮度、对比度、饱和度、锐化、alpha 阈值（一键抠背景）
- **去除背景色**：底色**可选**（默认白，也能填绿幕/黑底或直接取色），
  两种模式：只去与画面边缘连通的区域 / 全部近底色像素
- **实时预览**：所有参数改动即时重算，可侧滑分割对比原图

### 调色板引擎
- 内置 9 块调色板：Minecraft 染料 16 / MC 混凝土 16 / PICO-8 / GameBoy 4 / NES 子集 24 /
  C64 / DawnBringer 16 / 灰阶 8 级 / 黑白 2 色
- 从图片自动提取主色（中位切分 / k-means），可排除透明像素、限定明度区间
- 导入 / 导出 `.hex`、`.gpl`（GIMP Palette）、`.pal`（JASC-PAL）、色条 PNG
- **一键全局换色**：`Shift+点色块` 把全图某色替换成前景色（含手改区域，可 Ctrl+Z 撤销）—— 改素材主色调不用重画
- 逐个色槽改色（原生取色器）、按明度/色相排序、合并近似色
- **明度阶梯**：以当前前景色为基准，一键生成 3 / 5 / 7 档明度变体（在 CIELAB 里只改 L*，
  色相与饱和度不动，暗部不会发黑、蓝色不会偏紫），追加在调色板末尾并自动切换前景色
- 自定义调色板持久化，关掉浏览器再打开依然在
- k-means 限色模式：让图片自己决定用哪 N 种颜色

### 像素编辑器
- 工具：铅笔、橡皮、油漆桶填充、吸管、直线、矩形、椭圆、选区移动
- 撤销 / 重做（100 步命令栈）
- 缩放 1x–64x、网格线开关、像素坐标与色号实时显示
- **对称镜像**：水平 / 垂直 / 四向 —— 做角色素材的神器
- **双层模型**：转换结果是底层，手工改动叠加在编辑层；调转换参数不会毁掉你的手改
- 原图半透明叠加对照（onion skin）

### 智能辅助
- **去除背景色（去白底）**：把白底 / 绿幕这类实色背景变透明。
  默认**从画面四边泛洪**，只擦掉与边缘连通的部分 —— 主体内部的白色（眼睛高光、白衣服、白字）不会被误杀
- **自动描边**：给非透明区域外缘自动加 1px 轮廓（可选 4/8 邻域与外缘/内缘/两侧）
- **自动明暗**：按亮度自动分层为高光 / 中间调 / 阴影，**不改变色相** —— 只压明暗层次，红苹果不会被压成灰色
- **按 alpha 去背**：给**已经带透明通道**的图用（抠好的 PNG）。白底照片每格 alpha 都是 255，得用上面的「去除背景色」
- **边缘色晕清理**：消除半透明边缘残留的背景色（绿幕边、白底灰边）
- **平铺预览与接缝检查**：3×3 重复预览直接看无缝效果，对不上的边界格在画布上标红
- 原图半透明叠加对照（onion skin），描线时对位置
- 以上操作全部写进手改层，**每一个都能 Ctrl+Z 撤销**（预处理类参数改动除外，那是参数不是手改）

### 导出
- **PNG**：1x 原始像素，或 2x–64x 最近邻放大（不发虚），可选透明/白底/黑底
- **网格 JSON**：`{w, h, palette, indices, alpha?}` —— 给程序消费；全不透明时自动省掉 alpha
- **Aseprite 工程 `.ase`**：一帧一图层、32 位 RGBA，双击进 Aseprite 就能继续画或做动画
- **精灵图集**：把批量队列里已完成的图打成一张大图 + 坐标 JSON（每格等大、可裁透明边、可留白）
- **Minecraft 建造蓝图**：
  - 带行列坐标标尺的施工图 PNG，可按每页格数**分页**（适配纸张）
  - `x,y,z,block` CSV，Y 轴方向可选，照着能在游戏里一格格摆出来
  - 色号 ↔ hex ↔ 方块名对照表
  - **可编辑的方块映射表**：默认按颜色距离自动挑最近方块，改过的会记住
- **调色板文件**：`.hex` / `.gpl` / 色条 PNG
- **复制到剪贴板**：像素图（PNG）或调色板色值文本

### 存档与预设
- **`.pixproj` 存档**：源图、转换参数、调色板、转换结果与**手工修改**一起存进一个文件；
  顶栏「存档」/「打开存档」，第二天打开就是昨天那个状态（源图是内嵌的，不用重新选文件）
- **转换预设**：把一套参数存下来，换张图一键套用
- **快捷键面板**：`?` 唤起，把全部按键列清楚
- 自定义调色板、批处理预设、方块映射表都自动存在本地，关掉浏览器还在

### 批量处理
- **多图队列**：一次拖入一批图（也可点选多选），逐项缩略图 + 状态（待处理 / 转换中 / 完成 / 失败）
- **共用一套批量参数**，个别项可单独改目标格数
- **命名模板**：`{name}` / `{w}` / `{h}` / `{scale}` / `{index}`，同名自动去重（不区分大小写，避免 Windows/macOS 上互相覆盖）
- **一次打出 zip**：每张图的 PNG + 用到的调色板 `.hex` + `report.txt`（逐张尺寸/用色/耗时）
- 队列里任意一项可**送进主编辑器单独微调**（源图与参数一起带过去）
- **批处理预设**：参数 + 命名模板 + 放大倍数一起存取
- **并排对比**：把已完成的那几张连同原图一起铺开（棋盘格标出透明区），
  一眼看出哪张的底色去过头了、哪张的调色板偏了
- 批量转换跑在**独立的 Worker** 上，后台出素材的同时编辑器照常可用

## 快速开始

```bash
npm install
npm run dev              # 打开 http://localhost:5173
npm test                 # 运行 core/ 与 cli/ 的单元测试
npm run build            # 产出 dist/，用任意静态服务器托管（如 npx serve dist）
npm run build:offline    # 产出 dist-offline/index.html，单文件，双击即可用
npm run build:cli        # 产出 dist-cli/pixcli.mjs（命令行版）
```

### 三种打开方式

| 方式 | 命令 | 说明 |
| --- | --- | --- |
| 开发 | `npm run dev` | 改代码即时刷新，日常用这个 |
| 静态托管 | `npm run build` → 把 `dist/` 交给任意静态服务器 | **推荐**。Web Worker 正常，拖参数不卡 |
| 离线单文件 | `npm run build:offline` → 双击 `dist-offline/index.html` | 拷到任何电脑都能开，但见下面的限制 |

**离线版的已知限制**：浏览器不允许从 `file://` 加载独立的 Web Worker 脚本，
所以转换会退回**主线程**执行（状态栏会显示「已降级 主线程」）。
功能一个不少，只是拖动「目标格数」这类参数时会略卡。
想要完整性能就用静态服务器打开 `dist/`，或直接 `npm run preview`。

离线构建还会去掉 Google Fonts 的外链，改用系统字体 —— 既然叫离线版，就不该有网络请求。

**预处理与去背**（右侧「预处理与去背」分组）里有两套去背手段，别用错：

| 情况 | 用什么 |
| --- | --- |
| 白底 / 绿幕照片、AI 生成图（背景是**实色**，整张不透明） | **去除背景色**，模式选「只去边缘」 |
| 抠好的 PNG（背景**已经是透明**的，只是 alpha 不够干净） | **透明阈值**（α 小于阈值的算背景）+ 边缘色晕清理 |

「去除背景色」用的是从画面四边泛洪：只有和边缘连通的近底色区域才会被擦掉，
所以主体内部的白色（眼睛高光、白字、白衣服）是安全的。
底色默认是白，但**可以改**：绿幕、纯黑底、或直接拿取色器从图上点一下都能用；
容差决定「多接近底色才算底色」——默认 24 意思是每通道相差 ≤ 24 才算，
**别把容差调到超过主体最亮的浅色**，那样主体也会开始被啃掉。
「边缘软化」会把紧贴背景的那一圈过渡色变成半透明，避免留下硬白边；
打开它时建议同时开「边缘色晕清理」，那些半透明像素的颜色才会被换成主体色。

**绘图**只在画布显示像素图时生效（「仅结果」视图整张可画，「侧滑分割」视图在右半侧可画）。
手工修改存在独立的编辑层：调整转换参数、换抖动算法都不会覆盖它，只有网格尺寸变化时按比例重采样。

**导出**（右侧「导出」分组）：先选格式，下面的参数由格式自带（选 PNG 时就是放大倍数与底色）。
「多个文件时打包成 zip」默认开启 —— 分页蓝图一导就是好几张图，逐个下载会被浏览器拦下。
蓝图那条线会在下面列出**方块映射表**：默认按颜色距离自动挑了最近的方块，
不满意就逐个改，改过的会记住；CSV 与图纸图例用的是同一份映射，不会对不上。

**调色板**（右侧「调色板」分组）：选板、改单个色槽的颜色、排序、合并近似色。
「明度阶梯」按当前前景色一次生成 3 / 5 / 7 档变体（只改明度、不动色相），适合给同一个色找阴影与高光；
「提取主色」分组可以从当前图聚出 N 个主色并存成自定义板；
「调色板文件」分组负责 `.hex` / `.gpl` / `.pal` 的导入与 `.hex` / `.gpl` / 色条 PNG 的导出。

**批量处理**（右侧「批量处理」分组，默认折叠）：把一批图拖进队列 → 设好这套批量参数
（或点「从当前参数同步」把「转换」面板那套抄过来）→ 开始转换 → 导出 zip。
命名模板里的 `{name}` 是源文件名，`{index}` 是队列序号；同名会自动加 `_2`、`_3`。
队列里每一项都能展开，勾「独立目标格数」单独改尺寸，或点「在编辑器中打开」跳去手改。
手改之后记得点该项上的**「写回队列」**—— 手改住在编辑层里，不写回的话 zip 拿到的还是未经手改的结果。
批量参数是**独立的一份**，所以批量在后台跑的时候，编辑器里的预览照常调。
跑完点「并排对比」可以把已完成的那几张铺开看（可切换「对照原图」逐张比对）。

**颜色来源**（右侧「转换」分组）可在「固定调色板」与「k-means 限色」之间切换 ——
后者让图片自己聚出 N 种代表色，适合「先看看这张图本来长什么样」。

**转换参数**（右侧「转换」分组）：目标格数、采样方式（面积平均 / 最近邻 / 主色投票 / 中位数）、
颜色距离（加权 RGB / CIELAB / 欧氏 RGB）、抖动算法（Atkinson / Floyd / Sierra /
Bayer 2·4·8 / 不抖动）、抖动强度、亮度 / 对比度 / 饱和度 / 锐化 / 透明阈值、
pixelPerfect、裁掉透明边。

转换在 Web Worker 中执行，参数改动即时重算；拖动滑块时会自动降级到加权 RGB 距离
保证跟手，松手后再跑一次完整精度。

## 命令行批量转换（pixcli）

网页版的批量队列要手工点，如果素材是脚本生成的（一次几百张），用命令行更省事。
它复用同一套 `core/` 逻辑，所以出来的像素图与网页版**参数一一对应**。

```bash
npm run build:cli                              # 打包出 dist-cli/pixcli.mjs
node dist-cli/pixcli.mjs --help                # 看完整参数
# 也可以：npm run pixcli -- --help（或 npm link 之后直接用 pixcli）

node dist-cli/pixcli.mjs ./raw --out ./px --width 32 --palette mc-dye \
  --dither atkinson --scale 4 --json
```

| 常用参数 | 说明 |
| --- | --- |
| `--out <dir>` | 输出目录（默认 `./out`） |
| `--width` / `--height` | 目标格数，`--height auto` 按原图比例（默认） |
| `--palette <id>` | `mc-dye` / `mc-concrete` / `gray-8` / `mono` / `pico8` / `gameboy` / `nes` / `c64` / `db16` |
| `--palette-file <path>` | 读 `.hex` / `.gpl` / `.pal`，优先于 `--palette` |
| `--colors <n>` | 改用 k-means 限色 n 色（覆盖调色板） |
| `--sampling` / `--dither` / `--distance` | 与网页版同名选项 |
| `--remove-bg edges|all|none` | 按颜色去背景，配 `--bg-color` 与 `--tolerance` |
| `--no-trim` | 不裁掉四周透明边（**命令行默认会裁**，与网页版相反） |
| `--name <模板>` | `{name}` `{w}` `{h}` `{scale}` `{index}`，默认 `{name}_{w}x{h}.png` |
| `--json` | 每张同时写一份网格 JSON（与网页版同格式） |
| `--config <path>` | 从 JSON 读一套参数，命令行上的选项覆盖它 |

几点约定：

- **只支持 PNG 输入**（JPEG / WebP 请先转成 PNG）。8 位、非隔行；16 位与隔行会给一句可读的报错，不会静默出错。
- 文件名里的 `{w}`/`{h}` 是**裁剪后**的尺寸，所以命名要等转换完才算；
  跨整个批次去重（同名自动加 `_2`、`_3`），不会因为两张都叫 `hero.png` 就互相覆盖。
- 单张失败不会中断整批：坏图记一行 `✗`，其余照常出图。退出码 0 = 全成功，1 = 有失败（方便接进脚本）。
- 调色板 id 写错时会退回第一块并**明说一句**，不会悄悄换板让你以为参数生效了。

| 构建 | Vite + TypeScript（strict） | 起手快、零配置、可打包成离线静态文件 |
| UI | React 19 | 面板/控件多，组件化收益明显 |
| 状态 | Zustand | 轻量、可在 React 之外读写（画布与工具函数需要） |
| 绘图 | Canvas 2D + OffscreenCanvas | 逐像素操作 API 直接，缩放用 `imageSmoothingEnabled=false` |
| 重计算 | Web Worker | 转换流水线不阻塞 UI，帧数据通过 transferable 零拷贝传递 |
| 外部依赖 | 只有两个构建期依赖：`vite-plugin-singlefile`（离线单文件）与 `esbuild`（打包 CLI） | 运行时不引任何第三方库：zip 打包、导出、PNG 编解码全是自己写的 |

**无后端、无网络请求**：所有图像处理在浏览器本地完成。
唯一的外链是 Google Fonts（只为界面字体，不涉及你的图片）；离线构建会去掉它，改用系统字体。

## 设计原则

1. **参数可逆，手改不丢** —— 转换与手工编辑分层存储；调参数不会清掉你画的东西。
2. **纯本地** —— 不联网、不上传、不依赖账号；离线构建连字体都不外链。
3. **逻辑与 UI 分离** —— `core/` 是纯函数，可单独测试；命令行版（`cli/`）就是直接复用它，
   没有为「跑在 node 上」重写第二套转换逻辑。
4. **不追求全自动** —— 自动算法负责出草稿，最终效果由你的手决定。
5. **两套持久化，各管一段** —— 「一份工作」显式存进 `.pixproj`；
   「长期偏好」（调色板、预设、方块映射）自动存进 localStorage。
